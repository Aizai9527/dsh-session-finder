# dsh-session-finder v0.7.0（2026-10-30）

跨会话搜索 DSH 聊天记录，并**跳转到命中的那条消息**。

DSH 自带的搜索会打开会话但不滚动到命中位置，因为搜索响应里只有 `{ sessionId, snippet }`，没有事件坐标。这个插件补上最后一跳：打开会话后，用命中片段在已渲染的聊天 DOM 里找回那条消息，展开折叠节点、滚到视口中间并高亮几秒。

v0.2.0 起自带搜索通道，不走宿主 `sessions.search`——部分部署把会话索引配成 `openAt: "never"`，那条 RPC 一律报 `SESSION_QUERY_SEARCH_DISABLED`；插件改为在宿主半通过 `ctx.sessionPersistence` 直接读会话日志。

v0.3.0 解决三个实际使用问题：搜到的是 AI 思维链（渲染层根本没有这段文字，跳转必然失败）、系统提示里的通用词命中所有会话、以及结果没有分页只能看最新 48 个会话。

v0.5.0 解决「已经打开会话，但内容没跳过去」：插件原先只会把聊天滚动到顶部指望分页追上（`scrollTop = 0`），对长历史等于永远等不到。现在改为调用会话视图自己的 `ISession.loadThrough(seq)`（应用内「跳转加载」：向后翻页直到事件窗口覆盖该 seq），文字真正渲染出来后再定位、描边。同版本还加了搜索范围（当前会话 / 全部会话 / 指定项目，默认当前会话）与面板拖动。

v0.6.1 解决「会话已打开，但这段内容还没有渲染出来」：单次 `loadThrough` 在会话控制器还没 `open` 时会立刻返回什么也不做，长历史的命中就永远等不到。现在改为在轮询期间反复调用（最多 10 轮、每 6 次轮询追问一次），用会话面自己的 `baseSeq` 判断窗口是否真的覆盖目标 seq，期间状态行显示「正在自动加载更早的历史（第 n/10 轮）…」；没有进展时等待而不是继续排队，跳转一旦落定立刻停止后台加载。同时新增第三级锚点：宿主按事件的 `turn`（自带 `data.turn`，用户消息继承最近的 `turn/start`）回传，客户端可用 `data-chat-turn` 直接落到那一轮——折叠的工具输出根本不会变成可见文本，也能落到正确的轮次而不是报「没渲染出来」。

v0.5.1 解决「几个不同的结果都跳到同一处高亮」：工具调用行在聊天里只渲染一行摘要，参数正文处于折叠态，片段文字根本不在 DOM 里，于是每次都退化成用关键词兜底、落在同一个已渲染的消息上。现在宿主半把工具事件的 `callId` 随命中返回（`tool/call` 取自身 `callId`，`tool/result` 取 `message.toolCallId`），客户端先用聊天行上的 `data-chat-call-id` 精确定位；同一查询内已用过的行会被记住，文本匹配只会选没被占用的行，多条相同文本的结果也能依次落到各自的锚点。
             新搜索或关闭浮层会让仍在轮询的旧跳转作废（`state.jumpId` 计数 + 每次轮询前校验），上一轮的跳转不会再在用户走开之后把旧位置描上去。

v0.6.0 加搜索历史：输入框为空时，下方列出最近 10 次真正执行过的查询（最新的在最上面，重复的只留一条），点一条立刻重搜，也可用 `↑` `↓` 在列表里走、`Enter` 取用；`Esc` 第一次只收起列表（浮层仍在，焦点回到输入框），第二次才关闭浮层；列表底部「清空历史」删除全部历史。历史只存查询字符串本身，存在 `localStorage` 的 `dsh-session-finder:history`，不记录命中的会话、时间或任何消息内容。

v0.7.0 提速：范围＝当前会话本来就只要 0.15 秒，慢的是「全部会话」这一档——72 个会话、72 M 字符，每次都要重新解压和解析。三处改动：① 提取结果按「会话 id + revision」落盘到 `~/.dsh/cache/dsh-session-finder`（gzip 的 JSON，最多 240 个文件，日志一旦增长 revision 变化就自然失效），插件启动 4 秒后在空闲时逐会话预热，实测重启后首次宽范围查询 10.2 秒 → **1.7 秒**，重复查询 0.3 秒；② 单次请求预算 8 秒 → 2.5 秒、每页 48 → 150 个会话，并且 6 个会话并发读取（实测提取是 CPU 密集型，并发本身只省 2%，真正的收益来自缓存）；③ 命中后的定位省掉白等：点击即开始 `loadThrough`（原先要等到第 6 次轮询）、收起态跳过两轮 200/420 ms 的避让等待、用 `MutationObserver` 代替固定 120 ms 轮询、鼠标停在结果行上时预取该条历史。

## 安装

```powershell
# 从 npm
dsh plugin add dsh-session-finder

# 或直接从 GitHub
dsh plugin add github:Aizai9527/dsh-session-finder
```

装完重启桌面端：宿主半与客户端半都在启动时加载。仓库没有构建步骤，`lib/*.js` 就是分发产物。已在 DSH 插件市场（`awesome-dsh-plugin` 清单）登记。

## 用法

1. 快捷键 `Ctrl+Shift+F`（macOS 为 `Cmd+Shift+F`），或点右下角「搜索聊天记录」按钮。按钮可以按住拖动到任意位置，位置会记住（存 `localStorage` 的 `dsh-session-finder:trigger`）。
2. 输入关键词（至少 2 个字符）。**多个关键词用空格分隔，要求同时出现**；完全连写的短语排在同会话结果最前面。
3. 底部「搜索范围」决定扫哪些会话：**当前会话**（默认，自动识别左侧被选中的那一行或上次跳转到的会话）、**全部会话**、或某个项目。选择会立即用当前关键词重搜；识别不到当前会话时退回「全部会话」。
4. 结果按「命中的消息」列出，每条显示角色、时间与命中片段；同一会话最多 3 条，用户消息优先于助手回复，二者都优先于工具调用/输出。
5. `↑` `↓` 选择，`Enter` 打开并定位。`Esc` 先收起历史列表（浮层仍在），再按一次才关闭浮层。
6. **定位后搜索框不会消失，也不会挡住内容**：面板自动收起结果列表，只剩输入框、状态行和「上一处 / 下一处」，遮罩同时变透明（点击可穿过到页面）；点「**↑ 上一处**」「**↓ 下一处**」继续跳到下一条命中，也可按 `F3` / `Shift+F3` 或 `Alt+↓` / `Alt+↑`。走到当前页最后一条且还有更早会话时，会自动加载下一页再继续。
7. **面板可以拖动**：按住标题栏（输入框、按钮、下拉框除外）拖到任意位置，松手记住（存 `localStorage` 的 `dsh-session-finder:panel`），下次打开回到原处；拖动不会误触搜索或关闭。
8. **搜索覆盖整个会话，不只最近一段**：每个会话最多读取 8M 字符（此前是 400k，长会话的早期内容根本不会被索引）。超长会话仍可能有未读部分，状态行会写「另有 N 个超长会话只扫描了前段」。
9. **一次查询会自动翻页直到有所收获**：当前这页没有命中就继续读更早的一页（最多 4 页 / 20 秒），找到即停；全部读完仍没有才说「没有命中」，此时按钮会变成「继续搜索更早的会话」，不会谎报扫描完毕。
10. 收起状态下右上角是「**展开列表**」，点开可重新看到全部结果；在收起状态直接改关键词也会自动展开并重新搜索。
11. 定位后目标消息会被展开、滚到屏幕中间并描边高亮，**高亮一直保留到下一次跳转或关闭浮层**（不再 3 秒后自动消失）；若它会落在面板后面，会自动收起列表并再补一次滚动；会话已经滚到顶部、内容无法再移动时，面板改为停靠在底部（输入框上方），让出上方内容。
12. 结果底部有「**加载更早的会话**」时，点击继续扫描更早的历史（每次 150 个会话）；但如果本次查询在这一页里一条都没命中，按钮会写成「**继续搜索更早的会话**」，以免把「这一页没有」当成「全部没有」。
13. 命中的那一小段文字另有内层描边与底色，便于确认具体是哪一句。
14. 左侧会话列表里，刚跳到的那个会话行会被标出来：内嵌描边（`box-shadow: inset`，不会被列表的 `overflow` 裁掉）+ 更深的底色，并自动滚到可见位置；若该会话被折叠在分组里（「展开其余 N 个会话」），会先自动展开一次；切到别的会话或关闭浮层时旧标记自动清除；实在找不到时右下角提示「左侧列表没找到对应会话行」，不会静默失败。
15. 浮层右上角 `×` 或 `Esc` 关闭；关闭后遮罩恢复、命中高亮与左侧描边一起清除，下次打开回到居中搜索状态。
16. 浮层背景不依赖主题令牌：只接受页面 `body` 上「不透明且中性」的底色，遇到饱和色（例如品牌暖色）按主题回退到中性深/浅色，避免整块面板被染色。
17. 底部「不透明度」滑块可调浮层底色透明度（45%–100%，默认 100% 完全不透明），调整后写入 `localStorage` 的 `dsh-session-finder:opacity`，下次打开沿用。
18. **工具调用命中会落到那一行工具调用上**：聊天里的工具行只显示摘要，插件按工具事件自带的 `callId` 匹配行上的 `data-chat-call-id`，不再拿命令正文去猜；同一查询里已经跳过的行不会被第二条结果重复占用，所以「几条结果文本一样」时点下去也各有各的位置。
19. **搜索历史**：输入框为空时下方列出最近 10 次执行过的查询，点一条立即重搜；`↑` `↓` 在历史里移动、`Enter` 取用、`Esc` 收起（再 `Esc` 关浮层），底部「清空历史」清掉全部历史。只记查询串，不记结果与会话。

## 行为边界

- **只读会话，只写自己的缓存**：会话以 `read` 句柄打开，不写会话文件、不改日志。提取出的文本按「会话 id + revision」缓存在宿主内存（上限 64 M 字符），同时镜像到 `~/.dsh/cache/dsh-session-finder`（gzip，最多 240 个文件，超出的按 mtime 删最旧），所以重启后第一次宽范围搜索不必重读 70 M 字符；插件卸载时清空内存缓存。设 `DSH_SESSION_FINDER_NO_DISK=1` 可完全关闭磁盘缓存。
- **索引看得见的文字**：`user/message`、`assistant/message` 只取 `type: "text"` 的内容块；AI 的 `reasoning` 块和流式分块 `stream.chunks` 不索引，否则会搜出渲染层不存在的文字。`system/message` 和 `developer/message` 整类不索引——它们每个会话都一样，任何常见词都会误命中全部会话。`tool/call` 只索引工具名与参数字符串，`tool/result` 只索引输出文本。
- **注入块剔除**：用户消息尾部会追加 `<system-reminder>` 规则文本，提取时整块删除。
- **范围有界**：每次搜索扫最新 150 个会话，每个会话最多 3 条命中，总共 40 条，最长 2.5 秒，6 个会话并发读取；触顶时状态栏提示「已到单次上限」，`nextOffset` 从触顶的那个会话之后继续，可加载更早的会话。选了「当前会话」或某个项目时，先在宿主侧过滤再分页，页码从该范围的 0 开始。
- **跳转靠会话视图自己的加载器**：命中消息还没渲染时，插件在会话打开后取 `ctx.sessions.binding(sessionId).session`，调用它公开的 `loadThrough(seq)`（应用内「跳转加载」：向后翻页直到事件窗口覆盖该 seq），并反复追问直到 `baseSeq <= seq`，等文字出现后定位。没有进展时等待而不是继续排队；这次跳转一旦落定（成功或超时），后台加载立即停止，不再覆盖最后的状态行。拿不到会话面时退回「滚到顶部 + 提示再点一次」的旧路径，不会静默失败。
- **三级锚点，由准到宽**：① 工具命中用 `data-chat-call-id` 精确落到那一行；② 其余命中先用 `data-chat-turn` 落到那一轮（折叠的工具输出不会变成可见文本，但轮次行在屏上），再在轮内找命中文字描边；③ 都没有才按片段文字匹配。同一查询内已用过的行不会被第二条结果复用。
- **匹配靠片段文本**：用命中片段去匹配渲染后的文本节点；被 markdown 拆散时退化为按「消息块」匹配，位置精度会略降；短片段（中文两字以上）也保留兜底匹配。
- **工具命中靠 `callId` 精确锚定**：`tool/call`、`tool/result` 命中会带上事件里的调用 id，客户端直接找该行上的 `data-chat-call-id`，不需要命令正文出现在可见文本里（折叠态也能跳）。这类命中不再用关键词兜底，避免落到别处的同一句话上。
- **一条查询内不重复占行**：每成功定位一次就记住那个行元素，后续结果只选尚未占用的行；确有两条命中指向同一行时，第二条会如实报「还没渲染出来」，而不是假装跳过去了。
- **导航态仍靠文本匹配**：在命中间前后跳转时，每次都重新用该条的片段（或 `callId`）去当前会话里找锚点，不依赖消息 id。跨会话跳转会先点开目标会话再等它渲染。
- **历史只存查询串**：`localStorage` 的 `dsh-session-finder:history` 里只有最多 10 条查询文本，没有会话 id、命中内容或时间；输入框一有文字列表就隐藏，不会盖住结果；条目标签用 `textContent` 渲染，查询串里的尖括号不会被当成 HTML。

## 安装（当前安装方式：本地 link）

```text
profile: C:\Users\Admin\.dsh\profiles\desktop
依赖:    "dsh-session-finder": "link:C:/Users/Admin/Documents/deepseek-harness/default-workspace/dsh-session-finder"
bundles: 已追加 "dsh-session-finder"
```

**插件市场里安装/更新/卸载任意插件，可能把上面两项从 profile 的 `package.json` 里摘掉**，插件随即从界面消失。此时运行：

```powershell
cd C:\Users\Admin\Documents\deepseek-harness\default-workspace\dsh-session-finder
powershell -ExecutionPolicy Bypass -File .\relink.ps1 -Check   # 只检查
powershell -ExecutionPolicy Bypass -File .\relink.ps1          # 修复并重装
```

脚本只补回 `dependencies.dsh-session-finder` 和 `dsh.profile.bundles` 两项，其他依赖与配置原样保留；可重复运行。`-Check` 同时体检本插件的 `package.json`（BOM、JSON 合法性）：带 BOM 时插件市场会报「包不可用」，非 Check 模式会自动去 BOM。

> 改 `package.json` 时不要用会写 BOM 的方式（Windows PowerShell 5.1 的 `Set-Content -Encoding utf8` 会）。插件市场读清单不剥 BOM，只会在界面上报「包不可用」。

改动插件代码后需要**重启 DSH 桌面端**，宿主半的路由与客户端束才会重新加载。

## 结构

| 文件 | 职责 |
| --- | --- |
| `lib/index.js` | 宿主半：注册只读路由 `GET /session-finder/search?q=<query>&offset=<n>[&sessionId=…|&cwd=…]`（兼容旧路径 `<query>`），读日志、按范围过滤、并发打分、分页并返回命中；启动后空闲预热磁盘缓存 |
| `lib/search.js` | 宿主半纯函数：按事件类型提取可见文本、剔除注入块、片段切分、按 revision 的内存 + 磁盘缓存（`useDiskCache()`） |
| `lib/client.js` | 浏览器半：搜索浮层（可拖动）、范围下拉、搜索历史、结果列表（角色/时间/高亮）、加载更早、`loadThrough` 跳转与描边 |
| `test/needles.test.mjs` | 片段切分与归一化逻辑的单元检查（纯字符串，无 DOM） |
| `test/search.test.mjs` | 宿主半的可见文本提取、过滤、打分、分页参数与缓存检查 |
| `test/route.test.mjs` | 宿主半路由端到端：注册、入参、分页、拒绝连接 |
| `test/client-nav.test.mjs` | 命中间前后跳转的静态守卫：`choose()` 不得关闭浮层、导航控件与计数器必须在、跨页跳转要自动加页 |
| `test/client-inject.test.mjs` | 客户端服务声明的静态守卫：必须 `inject` 到 `sessions` 与 `uiWorkspace`，否则点结果无法切会话 |
| `test/client-target.test.mjs` | 定位后可看见性的静态守卫：高亮不得被定时器移除、`clearHighlight()` 是唯一清除入口、`markSidebar()` 必须重试并滚动到左侧行、两处标记都要有可见样式、内容滚不动时面板必须兜底停靠、折叠分组必须被展开、找不到行必须提示 |
| `test/client-paging.test.mjs` | 分页与覆盖的静态守卫：每会话读取上限不得低于 8M 字符、截断必须打 `partial` 标记、路由必须回报 `partialSessions`、一次查询必须自动翻页并在有命中时停止、无命中时的按钮文案不得谎报 |
| `test/client-scope.test.mjs` | v0.5.0 三项功能的静态守卫：`loadThrough(hit.seq)` 必须被调用且只调一次、`sessionId`/`cwd` 参数必须随查询发出、宿主必须按 `header.id`/`header.cwd` 过滤后再分页、范围下拉与「默认当前会话」必须在、面板拖动与位置持久化必须在 |
